## 一、一句话结论

R4 把「自动安装运行时」的后端地基做完了，但**界面上一个字都看不到**；这一轮把
**授权三档、状态机、主按钮、选盘卡片、文案**全部接到界面上，并且**选盘真的写进
`[runtime] data_dir`、真的被安装链路用到**（走 R4 那条配置路径，没有第二条写入路径）。

## 二、每张卡做了什么

### 2.1 后端补线（R4 留的接口缺口）

R4 的 `runtime/disk.rs` 是**纯函数 + 一次枚举**，`Volume` 连 `Serialize` 都没有，
也**没有任何 tauri command**（全仓对它的唯一引用是一句文档注释）。界面拿不到它，
所以本轮先补这一段：

| 改动 | 位置 | 说明 |
|---|---|---|
| `Volume` 加 `Serialize` + `rename_all = "camelCase"` | `src-tauri/src/runtime/disk.rs:78` | 界面要拿到**含系统盘**的整张表，才能说清「为什么不是 C 盘」 |
| 新增 `DiskPlan` / `PartBytes` 与 `plan()` | `runtime/disk.rs`（U-03 段） | 只给**事实**：「为什么是它」那句话由界面拼（界面才有 i18n） |
| 新增 `cap_gb()` / `used_gb()` | 同上 | **上限**与**实占**两个数，来源见 §2.5 |
| 新增 `target_dir(mount)` | 同上 | `<挂载点>/Hunter`，用 `Path::join` 拼（不自己拼字符串） |
| 三条新常量 + 一个**编译期**断言 | `runtime/disk.rs:49-61` | `DOWNLOAD/IMAGES/VM_BASE_BYTES` 与 `FIRST_INSTALL_BYTES`；`const _: () = assert!(FIRST_INSTALL_BYTES < NEED_BYTES)` |
| `paths::data_dir_usable` 提为 `pub(crate)` | `src-tauri/src/paths.rs:134` | 写入前过**同一道闸**（与 `runtime_dir()` 用的是同一个判据） |
| 两个新命令 | `src-tauri/src/commands.rs`（U-03 段）+ `lib.rs:247` | `runtime_disk_plan()` / `runtime_disk_set(mount)` |

`runtime_disk_set` 的输入是**挂载点**（不是路径）：
它会**当场重新枚举一次**盘、要求那块盘过 `eligible()` 三条与 `paths::data_dir_usable()`，
然后写 `[runtime] data_dir` —— 走的就是 R4 那条路（`LauncherConfig::save()` + `set_config()`）。
界面**递不进来一个任意路径**。传空串 = 改回默认位置。

**新增 Rust 单测 4 条**（`disk.rs` 11 → 15）：第一次装的量落在建议阈值之内 / 明细三块的键名与总量对得上 /
选中盘的落地目录叫 `hunter` / 选盘计划的三个数自洽（不依赖这台机器长什么样）。

### 2.2 U-01 · 状态机

`src/state/machine.ts`：

- 新增状态 **`ChooseRuntimeDisk`**（页面 `'disk'`，步骤条上归「自动安装」那一步）
- 新增事件 **`INSTALL_DOCKER`**（引导页「帮我装好 Docker」）与 **`RUNTIME_DISK_CHOSEN`**（选完盘）
- 转移：`InstallDockerGuide --INSTALL_DOCKER--> ChooseRuntimeDisk --RUNTIME_DISK_CHOSEN--> AutoInstalling`
- `BACK_TARGET`：选盘页退回**安装引导卡**（用户可能看完手动步骤想反悔）
- `ERROR_CODES` / `RETRY_TARGET`：新增 **`E_DISK_NOT_USABLE`**，`RETRY_TARGET` 指向
  **`ChooseRuntimeDisk`**（**不是** `AutoInstalling` —— 那边的重试会拿同一块盘再来一次，然后同样地失败）

`RECHECK_DOCKER` 那条老路一个字没改。

### 2.3 U-02 · `Docker.tsx` 主按钮

静态引导卡**上方**新增一张卡：说明 + 主按钮 **「帮我装好 Docker（不用你动手）」**
（`data-testid="docker-install-for-me"`），点了发 `INSTALL_DOCKER`。
下方由 Rust `install_guide()` 生成的手动引导**原样保留**。
`daemonDown` 时那一套（「尝试启动 Docker」）**一个字没改** —— 装了没起是「启动」，不是「安装」。

按钮文案是**结论不是问句**（「帮我装好 Docker（不用你动手）」）。

### 2.4 U-03 · 选盘卡片（新页 `src/pages/RuntimeDisk.tsx`）

四件事按用户心里的顺序排：**默认位置 / 为什么是它 / 会占多少 / 现在还剩多少**，
外加第二张卡专写**上限 vs 实占**、第三张卡写「接下来启动器会做的事」（L2 / L3 说人话）、
第四张卡是**能改选**。

- **默认位置**：`chosen` 指向的那块盘 +（若已有 Hunter）一个标记
- **为什么是它**：拿**真实数字**拼 ——「C:\ 是系统盘（还剩 18 GB），不往它上面装；D:\ 是剩下几块里空间最多的，还剩 212 GB。」
- **要占多少**：「第一次装大约 6 GB（下载运行时组件 0.4 GB + 六个服务的镜像 3.8 GB + 运行时磁盘底 1.7 GB）」
- **现在还剩多少**：选中盘挂载点 + 剩余
- **能改选**：列出所有非系统盘（含容量/剩余），选中后按「就装这块盘」才真的写配置
  （**写配置有副作用，不在勾选那一瞬间发生**）；另有「改回默认位置」
- **全不合格**（`chosen === null`，S-01 的正常返回值）**必须有话可说**：
  分两种 ——「有盘但空间不够」（算出**还差多少 GB**）与「连一块非系统盘都没有」

### 2.5 「上限 vs 实占」—— I14·F2 那 15 倍的教训

这两个数在 **Rust 那边就是两个字段**，在界面上**必须落在两行**：

| 数 | 来源 | 量不到时 |
|---|---|---|
| **上限** `capGb` | 优先用**虚拟机自己 `df` 报的总量**（真拿到的）；量不到再退回 `builtin::vm_params()` 那个常量（真正会传给虚拟机的 `--disk` 值），**而且只在 macOS 上退** | `null` → 界面写「量不到（运行时还没装起来）」 |
| **实占** `usedGb` | 只认虚拟机里 `df` 的**块级占用** | `null` → 分「还没装，所以是 0」与「量不到」两句 |

**绝不拿宿主上那个磁盘文件的大小顶替** —— colima / lima 与 WSL2 的虚拟磁盘都是
**稀疏文件**，`metadata().len()` 报的是「上限」而不是「用掉的」。
I14·F2 就是这么把 5.8 GB 报成 86.1 GB 的（差 15 倍），代码注释里写明了这一条
（`disk.rs` 的 `used_gb()`）。

界面那一侧也有对应断言：`src/lib/disk.test.ts` 里有一条
「上限与实占**不可能**被拼成同一个字符串（类型上就是两条路）」。

### 2.6 F-02 的前端（P1-48）· 授权页三个勾 + 设置页开关 + 审计人话

- **授权页**（`src/pages/Consent.tsx`）：三个勾（一级 / 二级 / 三级），每档下面一句用户看得懂的话；
  **默认值从后端读**（`read_settings().assistGrants`）—— 界面里**不写第二份默认值**
- **设置页**（`src/pages/Settings.tsx`）：新增「授权」那一栏，同样是三个勾，**改完立刻生效**
  （`write_settings` 当场写 `[assist] grants`、盖时间戳、写一条审计）
- **档位是阶梯**（`src/lib/grants.ts`）：后端 `GrantSet` 存的是**上限**，所以界面上的勾
  永远是一个**前缀** —— 勾三级含一二级；取消三级回到二级；取消一级 = 一档都不授权
- **审计**：`AuditLog` 从「把原始 JSON 倒进 `<pre>`」改成**先解成人话**：什么时候、谁做的、
  改成了什么（内容用 Rust `audit()` 写下的 `result` 那句，界面只摆出来、不再自己拼一遍）；
  解不开的行**仍然原样显示**，不让整块面板空掉
- **L2 / L3 实时说人话**：选盘卡片上「接下来启动器会做的事」两条
  ——「替你装运行时（二级授权）：只往 Hunter 自己的目录里写，不改系统、不要密码」
  与「如果必须往系统目录里写（三级授权），会弹系统自带的授权框 —— 密码交给系统，启动器看不到」

## 四、没做到的（如实列）

1. **真机界面走查没做**。这台机器没有图形环境，只有 Xvfb 下的演示构建截图。
   Windows / macOS 上的真实选盘（盘符、`D:\Hunter` 这种路径、WSL2 的 vhdx）**一条都没验**。
   验收清单见 §4.1。
2. **`runtime_disk_set` 没有在真机上写成功过一次**。演示模式下它只返回演示值。
   单测覆盖的是纯函数那一段（`target_dir` / `data_dir_usable` 的判据），
   命令本身的「真的把 `[runtime] data_dir` 写下去了、`paths::runtime_dir()` 真的跟着变了」
   **只在代码层面成立，没有端到端跑过**。
3. **上限那个数在非 macOS 上恒为「量不到」**。`cap_gb()` 只在「虚拟机 `df` 量得到」
   或「macOS（退回 `vm_params()` 常量）」时才有值；Linux / Windows 上是 `null`，
   界面如实写「量不到」。这是**刻意的**（不编一个数），但也意味着 Windows 用户
   在这一格里看不到上限 —— 要等 S-04 / W-13 那条链把 Windows 的路径定下来。
4. **S-04 没做**（R4 就没做，本轮也不在任务书里）：`builtin::vm_params()` 算虚拟机磁盘大小时
   读的仍是 `paths::root()` 所在盘（即系统盘），**不是选中的那块盘**。
   所以「上限」这个数与「装到 D 盘」在语义上还没对齐 —— 本轮只做到
   **如实把两件事分开写**，没有让它们真的联动。
5. **审计面板的「解成人话」那一屏没有截图证据**：它要点一下「看最近 20 条」才渲染，
   而截图脚本只截静帧。逻辑本身有 7 条单测钉着（`grants.test.ts`），
   但**没有一张图证明它在界面上长什么样**。
6. **授权三档的「生效」只在后端成立**：本轮验的是「界面把勾的结果送过去了」
   （`grants.test.ts` + `assist_consent` 的既有语义），
   **没有真机跑过「勾上三级之后某个提权动作真的执行了」**。

## 六、这一轮踩到的坑（写下来免得再踩）

1. **`sanitize` 一下：`Volume` 没有 `Serialize` 这件事，R4 的报告里写了，但只有真的去接线时
   才会发现「连一个数都拿不到」**。纯函数做完 ≠ 能用；中间隔着一层「暴露」。
   R4 报告 §4.2 已经如实写了「没有任何非测试调用方」，本轮把它补上了。
2. **真正上屏的文案不一定在你以为的文件里**。任务书指向 `src/i18n` 的三条键，
   但 Windows 引导真正的来源是 Rust 的 `install_guide()`，
   而且三条 i18n 键里至少两条是**死键**。做文案类需求时，
   「这个键真的渲染吗」值得先 grep 一次。
3. **Rust 侧的字符串不归 `i18n.test.ts` 管**，所以 `**这样**` 这种 Markdown 星号
   能在 Rust 里活很久（`check-wording.py` 也不扫 `runtime/docker.rs`）。
   这是检查网的一处结构性缺口，本轮顺手修掉了已发现的实例，**没有补检查**。
4. **上下文守卫报的数字可能是旧会话的**：本轮开工时钩子报「91%」，
   而 `context-guard.py --detail` 实测是本会话的 **3.0%** —— 钩子读的那份
   transcript 不是当前会话。**以脚本实测为准**（技能里也是这么写的）。
