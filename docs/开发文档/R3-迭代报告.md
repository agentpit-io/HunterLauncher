## 二、版本号改了哪几处

`scripts/set-version.sh 0.1.17` 一次改四个文件，逐处如下（都能在 `d83b093` 的 diff 里看到）：

| 文件 | 改前 | 改后 | 为什么这个文件也要改 |
|---|---|---|---|
| `package.json` | `0.1.16` | `0.1.17` | 前端的版本，标题栏右上角那行字读的是 `app_info` 给的值 |
| `src-tauri/tauri.conf.json` | `0.1.16` | `0.1.17` | 打包用它命名产物，`release.yml` 会拿它跟 tag 对账 |
| `src-tauri/Cargo.toml` | `0.1.16` | `0.1.17` | `env!("CARGO_PKG_VERSION")` 编译进程序，**updater 比的就是这个值** |
| `src/lib/demo.ts` | `0.1.16` | `0.1.17` | 演示数据里的版本号，**截图用的就是那个构建** |
| `src-tauri/Cargo.lock` | `0.1.16` | `0.1.17` | **不是 `set-version.sh` 改的** —— 见下 |

### 2.1 `Cargo.lock` 必须单独跟上

`set-version.sh` **不碰 `Cargo.lock`**。它是被下面这条命令带上的：

```bash
nice -n 10 ionice -c 3 cargo check --manifest-path src-tauri/Cargo.toml
```

输出 `Compiling hunter-launcher v0.1.17` / `Finished dev profile in 10.04s`，
`git diff src-tauri/Cargo.lock` 恰好一行：`[[package]] hunter-launcher` 的
`version = "0.1.16"` → `"0.1.17"`。

**不跑这一步的后果是 CI 直接红**：`--locked` 会因为锁文件与 `Cargo.toml` 对不上而拒绝
（任务书原话「否则 CI 的 `--locked` 会报锁文件过期」）。

改动全清单：`git diff --stat` = **6 个文件、46 insertions、5 deletions**
（CHANGELOG.md 41 行新增，其余 5 个文件各 1 行替换）。

### 8.1 这一轮最值得记住的一句

**「CI 红」和「代码坏了」是两回事，得看清楚再决定停不停。**

开工前那道闸要求「最近一次 CI 全绿」——它是为了保护「不要在没验证过的树上发版」。
这次拦下来的是**我们自己的 runner 连不上 `static.rust-lang.org`**，
而被拦的那棵树只改了 `docs/`。

处理它的方式**不是绕过去**（那才是真违规），而是**把那条没跑起来的 job 重跑一遍** ——
重跑验证的是同一棵树、同一个提交，**重跑绿了，这道闸才真正成立**。
判据是「同一棵树的 CI 到底绿不绿」，不是「页面上那个最新状态点是不是绿的」。

**如果重跑还是红，本轮就停在那里。**
