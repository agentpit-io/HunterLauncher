## 零、开工第一件事：国内源换香港区的核查

里程碑交代：M2 开工时读到的是广州地址，本轮先把它们换成香港区并补测试。

### 0.1 全仓 grep 的结果：代码里**本来就没有**广州地址

M2 执行到一半时用户已经把源切到香港区，M2 的实现跟着改过了。本轮逐项核对：

| 要找的东西 | 代码里 | 文档里 |
|---|---|---|
| `ccr.ccs.tencentyun.com`（广州镜像仓库） | **0 处** | 2 处，都是「广州区已停用」这句说明本身 |
| `hunter-dl-1253756459`（广州下载桶） | **0 处** | 0 处（下载桶要 M4 才用得上） |
| `registry.cn-hangzhou.aliyuncs.com`（方案里的阿里云 ACR） | **0 处** | 2 处，都是「实测不存在，已作废」的说明 |
| 界面文案「腾讯云 · 广州」/「阿里云 · 杭州」 | **0 处**，实际是「腾讯云 · 香港」 | — |

所以本轮不是「替换」，是**把这件事钉死，让它以后改不回去**：

1. **单元测试** `registry::候选源里不许出现已停用的广州区地址`
   —— 按**主机名整体**比而不是 `contains`。写第一版时正是用 `contains` 踩了坑：
   广州区是 `ccr.`，香港区是 `hkccr.`，前者是后者的后缀，`contains` 会把**正确的香港地址判成停用地址**。
   这条测试第一次跑就自己把自己抓了（第十二节 bug 1）。
2. **CI 闸门**：前端 job 第一步就 `grep -rInE` 全仓扫一遍这三个串（排除 `hkccr.`），命中即失败。
3. **测试机上用国内源从零拉一次**（下一节）。

M3 把上游 api 能读的接口**从容器里逐条探了一遍**（测试机 api 1.2.0，`/openapi.json` 是 404，
所以是拿路径一条条打的）：

| 路径 | 从本机打的结果 |
|---|---|
| `/api/health` | **200** |
| `/api/setup/status` | **200**（`via: "local"`，按来源放行） |
| `/api/setup/llm/quota` | **200** |
| `/api/setup/env-check` | **200** |
| `/api/chat/sessions` | 401 |
| `/api/user_sources`、`/api/user_sources/health` | 401 |
| `/api/signals`、`/api/alerts`、`/api/preference`、`/api/settings` | 401 |
| `/api/users/me/saas-config` | 401 |
| `/api/system/version`、`/api/system/metrics/daily` | 401（其实是根本没有这个路由，被 JWT 中间件先拒了） |
| `/api/internal/runtime/llm` | 401（要 `X-Hunter-Internal-Key`） |
| `/api/catalog` | 401 |

401 的那些要一个**登录用户的 JWT**。启动器手里没有，而且**不该替用户造一个**
—— 它有 `JWT_SECRET`（是它自己生成的），技术上签得出来，但那等于启动器给自己开了一个后门。

于是四张卡片：

| 卡片 | 来源 | 本轮状态 |
|---|---|---|
| 今日模型额度 | 网关 `GET /api/saas/llm/quota` | **真数字** 82,845 / 300,000 + 进度条 |
| 数据源 | `GET /api/setup/status` 的 `llm.builtin` + `data_supply.configured` | **真数字**（本轮接上）：「Hunter 网关」+「平台数据供给已配置 · 自有数据源个数需登录后才能读」 |

**「数据源」的副行没有写「自有数据源 0 个」**（视觉稿上是这么写的）：那个计数要登录态才读得到，
写 0 就是编。这一条在第十三节记为对视觉稿的有意偏离。

> ⚠️ 一个安全注意点写在 `upstream.rs` 的模块文档里：`/api/setup/status` 的响应里**带着打码后的
> key**（`hunt_tools_q6sK****QMo2` 这种形状，仍然露 4 位随机字符）。所以那个模块**只取自己要的
> 五个字段**，绝不把整个响应体塞进日志或诊断包。

### 2.2 Xvfb 下怎么把「每一项点一遍」真的做到

M0 §7.3 已经提醒过：**没有状态栏的环境里托盘图标是看不见的**，xdotool 点不着。
本轮的解法不是绕过去，是**给启动器加一个真实的遥控口**：

```
hunter-launcher --tray-menu <菜单项 id>
```

第二个进程带这个参数起来时，`tauri-plugin-single-instance` 把 argv 交给**正在跑的那个界面进程**，
它执行 `tray::run_action(id)` —— 和用户真点托盘菜单**走的是同一个函数**。
这既让验收做得成，本身也是 SSH 用户想要的能力（`--tray-menu stop` 比背 compose 命令容易）。

安全上收紧了两点：只认 `tray::MENU_IDS` 里真有的 id（不是任意字符串的口子），
而且这条路只在本机进程之间走（single-instance 用的是本地套接字 / 命名管道）。

**托盘在 Xvfb 下真的建起来了**（这一点比 M0 的预期好）：

```

```

但**图标是否目视可见、菜单是否渲染正确，无桌面环境下没法确认**（红线 5：写「未测」）。

### 2.4 开机自启（默认关）

三平台三套机制，都是**用户级**的，不碰系统目录、不要 root：

| 平台 | 落点 |
|---|---|
| Linux | `~/.config/autostart/hunter-launcher.desktop`（XDG 规范，认 `XDG_CONFIG_HOME`） |
| macOS | `~/Library/LaunchAgents/io.agentpit.hunter.launcher.plist` |
| Windows | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（调 `reg.exe`，**参数数组**，红线 3） |

**界面上的开关读的是系统里真实的状态**（`autostart::status()` 去看文件 / 注册表在不在），
不是 `launcher.toml` 里记着的那个可能已经和现实脱节的布尔值（红线 1）。

Linux 上真实切了两次：

```
$ ls ~/.config/autostart/          # 切之前
ls: cannot access ...: No such file or directory          ← 默认关，确认

# 托盘 → 开机自启
$ cat ~/.config/autostart/hunter-launcher.desktop
[Desktop Entry]
Type=Application
Name=Hunter Launcher
Comment=Hunter 启动器（开机自启 · 只出托盘不弹窗）
Exec=/home/support/HunterLauncher/src-tauri/target/release/hunter-launcher --minimized
Icon=hunter-launcher
Terminal=false
X-GNOME-Autostart-enabled=true
$ grep autostart ~/.hunter/launcher.toml
autostart = true

# 再切一次
$ ls ~/.config/autostart/          # 空
$ grep autostart ~/.hunter/launcher.toml
autostart = false
```

自启拉起来的那一次带 `--minimized`：**进程起来、托盘出现，但不弹窗**
（开机时糊用户一脸窗口是最招人烦的做法）。这个参数由 `lib.rs` 的 `minimized_arg` 认，
主窗口建出来时 `.visible(false)`。

### 2.5 退出询问：两条分支都真验了

方案原文：「退出时若容器运行中，询问『保持后台运行』或『一起停止』」。

做成了**界面里的弹窗**而不是系统对话框 —— 一来风格与其余页面一致，

### 3.2 模型模式切换 —— 本轮最重的一块，全程真跑

点「切换并重启相关服务」之后 Rust 侧做三件事，缺一不可：

1. **先真发一次请求验连通性**（`GET {base}/models`，不通再退一步发一次 `max_tokens:1` 的
   `POST {base}/chat/completions`）；不通就直接报错，不动任何配置。
2. 用当前配置 + 内存里的 key **重写 `.env`**。`write_env` 自带 sticky：
   `JWT_SECRET` / `POSTGRES_PASSWORD` / `OPENCODE_PASS` 会原样读回来，绝不换新。
3. `docker compose up -d --force-recreate api opencode llm-shim`，再等这三个服务健康。

> **第 3 步为什么不是 `compose restart`**：`restart` 只把进程重启一遍，
> **容器里的环境变量还是老的**。`.env` 改了要生效必须让 compose 重新创建容器。
> web / postgres / redis 不动 —— 它们不读 `LLM_*`，白重启只是让用户多等。

### 4.1 一个如实记下来的限制：容器日志里的中文

启动器的字体是**本地打包的子集**（方案要求离线可用，完整 Noto Sans SC 有 10 MB 上下）。
子集只含**仓库里出现过**的字形；容器日志里的中文（「迁移」「流水线」这类）不在其中。

- 在**没有系统中文字体**的机器上会显示成豆腐块 —— 测试机原本 `fc-list :lang=zh` 是 **0 个**，
  截图 [`10-日志-导出为文件.png`](../screenshots/M3/10-日志-导出为文件.png) 里能看到「□移」。
- `tokens.css` 的 `font-family` 里排了系统中文字体作为回落。**这条回落本轮真验了**：
  装上 `fonts-noto-cjk`（`fc-list :lang=zh` 0 → 30 个）之后同一页重截，
  「迁移」「流水线」全部正常 —— 截图
  [`11-日志-容器中文回落系统字体.png`](../screenshots/M3/11-日志-容器中文回落系统字体.png)。

结论：**不是 bug，是子集化的既定代价**，而且回落链路是有效的。
绝大多数桌面 Linux / Windows / macOS 都自带中文字体。已记进待办池 P2。

## 六、遥测（方案 §12，M3 要求 6）

### 6.1 三条硬约束，都有测试盯着

1. **开关默认关**。`enabled == false` 时 `record` 直接返回，**一个字节都不写**
   —— 连队列文件都不建（测试 `开关关着一个字节都不写`）。
2. **只收计数与枚举，不收自由文本**。字段值在类型层面就只有「字符串枚举 / 整数 / 布尔」三种，
   而且每个字符串还要过 `sanitize_value`。
3. **写盘前过脱敏**。`append_line` 是唯一出口，每一行先过 `redact`（测试 `队列里找不到_key`）。

### 6.2 第 2 条改过一次 —— 第一版拦不住股票代码

第一版的 `sanitize_value` 是**逐字符过滤**（把空格和中文滤掉）。测试一跑就发现：

```
输入：我在 600519 上试了半天，报错说 connection refused
第一版输出：600519connectionrefused        ← 股票代码原样留下来了
```

逐字符过滤**永远拦不住这种事**，因为自由文本里最敏感的部分（数字、代码）恰好都是合法字符。
改成**整条拒收**：带空白、带非 ASCII、超过 48 字符的值，整个变成 `invalid`，一个字符都不留。
合法枚举值（`ghcr`、`DockerEngine`、`29.8.1`、`zh-CN`、`E_PULL_FAILED`、
`hkccr.ccs.tencentyun.com/agentpit`）逐个断言不被误伤。

`libwebkit2gtk-4.1-0, libgtk-3-0, libayatana-appindicator3-1, libayatana-appindicator3-1, libwebkit2gtk-4.1-0, libgtk-3-0`
—— 每个包两遍。原因是 `tauri.conf.json` 里手写了一份 `deb.depends`，
而打开 `tray-icon` 特性之后 Tauri **自己也会加同样三个**。删掉手写的那份就干净了。
CI 里加了一条断言：`Depends` 里必须有 `libayatana-appindicator3-1`（漏了它，很多桌面上托盘直接不出现）。

### 7.3 AppImage 真实运行

```
$ file 'Hunter Launcher_0.1.0_amd64.AppImage'
ELF 64-bit LSB pie executable, x86-64, static-pie linked, stripped
$ ./'Hunter Launcher_0.1.0_amd64.AppImage' --appimage-extract-and-run
```

窗口出来，真实数据（6/6 健康、额度 82,845、端口 3101），托盘 11 项建立成功。
截图 [`16-AppImage运行.png`](../screenshots/M3/16-AppImage运行.png)。

> 用 `--appimage-extract-and-run` 是为了不依赖 FUSE（这台机器上 `/dev/fuse` 其实在，
> 但服务器 / 容器环境常常没有，验的是更普适的那条路）。

### 7.4 文件名里的空格

Tauri 用 `productName`（"Hunter Launcher"）当文件名，带一个空格。装包能装，
但下载地址里会变成 `%20`，命令行里每次都要加引号。
**CI 里加了一步改名**成 `hunter-launcher_<版本>_amd64.{deb,AppImage}`，
M4 的发布流水线要用同一套命名往 COS / Release 上传（已记进待办池）。

## 十二、本轮真实测试撞出来的 7 个问题（都已修并补了测试）

### bug 1 · 「禁止广州地址」的测试把**正确的香港地址**判成了违规

第一版用 `prefix.contains("ccr.ccs.tencentyun.com")` 判。
广州区是 `ccr.`，香港区是 `hkccr.` —— **前者是后者的后缀**，于是正确的
`hkccr.ccs.tencentyun.com/agentpit` 也命中了，测试第一次跑就红。
改成按**主机名整体**比（`assert_ne!(c.host, h)` + `starts_with(format!("{h}/"))`）。
CI 的 grep 闸门同样要 `| grep -v 'hkccr\.'`。
**一条写错的守卫比没有守卫更坏** —— 它会逼着后来的人去改正确的代码。

### bug 2 · 界面上冒出豆腐块：字体子集只扫了前端源码

运行面板第一版截图上是「平台数据**□**给已配置」。
原因：`scripts/build-fonts.py` 只扫 `src/`，而「平台数据供给已配置」这句话是
**Rust 拼好再交给界面显示的**（`upstream.rs`），「供」字压根不在子集里。
后来在退出弹窗（「器**□**?」= 器吗）、反馈页（「**□**要」= 概要）上又出现了几处。

修法两步：`build-fonts.py` 一并扫 `src-tauri/src/*.rs`（子集 997 → 1002 个汉字，
woff2 215 KB → 272 KB）；再加一条**不需要 fontTools 的** `scripts/check-fonts.py`，
把生成时用的字符集记进 `src/assets/fonts/charset.txt`，CI 里对账。
这条检查当场就抓到我后来新写的注释里的「冤枉茅跌堆」五个字没覆盖。

### bug 3 · 日志页与诊断包只给了「这一次运行」的日志

`log::tail()` 返回的是**进程内存里的环**。用户点开日志页多半是因为**上一次**运行出了问题，
页脚却写着「最近 400 行」—— 这是误导；诊断包附一份只有三行的启动器日志，对排查毫无用处。
新增 `log::tail_file()` 读落盘的 `launcher.log`（不够时把上一卷 `.1` 也接上），
日志页、诊断包、`--diagnose`、运行面板的日志框全部改过去。
补了一条正反都断言的测试（文件里能看到上一次运行的行，内存环里看不到）。

### bug 4 · 遥测的「不收自由文本」第一版拦不住股票代码

逐字符过滤 → `600519connectionrefused`。改成整条拒收。详见 §6.2。

### bug 5 · `pkill -f "release/hunter-launcher"` 把自己和别的测试都杀了

测试脚本里这条 pkill 的模式串会匹配到**包含这串字符的 ssh 命令自身**（ssh 直接退出码 255），
也杀掉了正在后台跑的 headless 拉取测试（国内源那次第一遍只跑到「准备配置」就 `Terminated`）。
全部改成 `pkill -x hunter-launcher`（按进程名精确匹配）。
**工具脚本里的 pkill 模式太宽，和产品代码里的 bug 一样会坏事。**

### bug 6 · 被打断的打包留下一个「能骗过 ls」的半成品

上面那次误杀发生在 AppImage 打包中途，留下一个 7.98 MB 的 `.AppImage` 文件。
差一点就把它当成「AppImage 只有 8 MB」写进报告（与 M0 实测的 74 MiB 差了一个数量级）。
重打之后是 75.11 MiB。
**教训：产物的体积要和历史实测对一对，差一个数量级时先怀疑产物本身。**

### bug 7 · CI 的「禁止广州地址」闸门第一次跑就把自己判违规

第一版把违规地址的名单直接写在 `ci.yml` 的 `BAD='…'` 里，而扫描范围包含 `*.yml`
—— 于是这份 yml 自己命中了 `hunter-dl-1253756459`，前端 job 直接红。
`registry.rs` 里那条守卫单测同理：它必须把违规字符串原样写出来才比得了。

修法不是「整文件豁免」（那会把一整个文件变成盲区），而是给一个**逐行**的豁免标记
`retired-mirror-ok`，并把名单挪进 `scripts/check-retired-mirrors.sh`。
正反两向都验过：干净时退出码 0；往 `src/lib/` 里塞一个带广州地址的文件，立刻退出码 1 并指出文件与行号。

**这条和 bug 1 是同一类错误的两次复发** —— 守卫代码里必然出现它自己要禁的东西，
写守卫时得先想清楚「它会不会抓到自己」。

另外两处不算 bug 但也是真跑才发现的：
**运行面板前三秒写「拿不到真实数据」是冤枉自己**（第一次拉数据要走 docker ps + 额度 + GitHub
三个往返，几秒钟，这期间应当显示「读取中…」而不是「拿不到」）；
**`.deb` 的 `Depends` 每个包出现两遍**（§7.2）。

## 十四、需上游配合（hunter-community）

M0 提的 8-1 ~ 8-5 五条**本轮仍然全部成立**。M3 逐条实测之后，把「启动器要什么」说得更具体：

| # | 要什么 | 用在哪 | 现状 |
|---|---|---|---|
| 14-1 | `GET /api/system/metrics/daily`：当日对话数、深度分析次数 | 运行面板「今日对话」卡 | 不存在。`/api/chat/sessions` 有，但要登录用户的 JWT |
| 14-2 | 晨报开关与推送时间的**免登录只读**版（或并进 14-1） | 运行面板「晨报」卡 | 不存在 |
| 14-3 | `GET /api/user_sources` 的**免登录只读计数** | 「数据源」卡的副行（稿子上的「自有数据源 N 个」） | 现在是 401 |
| 14-4 | `GET /api/system/last-tool-call`：最近一次工具调用的脱敏摘要 | 反馈诊断包（方案 §11.1 点名要的一节） | 不存在。诊断包里这一节默认不勾并写明原因 |

**共同的约束**：这四条都应当像 `/api/setup/status` 那样**按来源放行**（本机 / 内网），
或者接受 `HUNTER_INTERNAL_KEY`。启动器有 `JWT_SECRET`（它自己生成的），
技术上签得出一个管理员 token，但**那等于启动器给自己开后门**，本轮明确不这么做。

另外记一笔（不是要求，是提醒）：`/api/setup/status` 的响应里带着打码后的平台 key
（`hunt_tools_q6sK****QMo2`），**仍然露 4 位随机字符**。启动器已经做到只取需要的字段、
绝不整体转存，但这个接口如果哪天被代理给浏览器，那 4 位就出去了。

1. **发布流水线要用的东西已经就位**：`.deb` / `.AppImage` 在 CI 里每次都打，

   COS 上传、`latest.json`、Tauri updater 端点（COS 在前 GitHub 在后）是 M4 的活。
2. **`plan/国内镜像与下载源.md` 第二节的下载桶** `hunter-dl-hk-1253756459` 本轮**一次都没用到**
   （启动器还不需要下载自己）。M4 第一次用它时注意：那个桶的默认域名会强制下载而不是浏览器预览。

   托盘的「检查更新」现在只是告诉用户有没有新版本，**还不会真去升级**。
4. **别踩的坑**：
   - 测试脚本里的 `pkill` 一律用 `-x`，`-f "release/hunter-launcher"` 会把 ssh 自己和别的后台任务一起杀掉（bug 5）；

     M3 在它上面加了 `tray <菜单项 id>` 子命令。

   **网关**），旧栈跑在 3100（项目名 `hunter-community`），两套都 healthy。
