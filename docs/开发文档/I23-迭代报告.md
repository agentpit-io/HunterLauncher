## 一、背景与需求来源（来自用户真机体验反馈）

1. **小内存笔记本安装「拉不动」，事先毫无提醒**：
   - 用户在笔记本上安装 Hunter 时，由于笔记本内存较小，同时拉起 6 个容器服务（`web` / `api` / `atomcode` / `llm-shim` / `postgres` / `redis`）时拉不动，准备换台式机再试。
   - 此前启动器仅做了磁盘空间检查（`runtime/disk.rs`），在欢迎页和安装前对**电脑总内存、当前空闲内存、CPU 核数、系统版本与容器引擎分配内存**没有任何前置体检与分级提醒。
   - 同时，`src-tauri/src/runtime/builtin.rs` 的 `vm_params()` 把内置虚拟机内存固定为 `(mem_gib / 4).clamp(4, 8)`，导致 8 GB 内存笔记本被划走 4 GB 给虚拟机，加上宿主系统占用容易触发剧烈 Swap 卡死。
2. **Windows 环境自动安装 Docker 最大化消除手工操作**：
   - 用户要求在 Windows 环境下最大化减少用户在系统向导和界面外需要手工操作安装 Docker 的过程：自动检查环境、预写 `.wslconfig` 限制内存、预写 `settings-store.json` 跳过英文欢迎页、双源高速下载安装包并支持静默安装到非 C 盘（如 `D:\Hunter`），首次启用 WSL2 需重启时自动写 `RunOnce` 注册表实现重启登录后自动续装。

## 二、本轮改动清单

1. **新增全平台硬件环境体检模块（`src-tauri/src/hwcheck.rs`）与 Tauri 命令**：
   - 定义三档硬件评级 `HwLevel`（`Good` 绿灯 / `Tight` 黄灯 / `Insufficient` 红灯）、单项检查结果 `HwItem` 与完整报告 `HwReport`。
   - 抽取出纯函数 `evaluate(&RawHwInput) -> HwReport`，对 5 项实测指标分级判定：
     - **电脑总内存（`memory`）**：`< 7.5 GiB` → `Insufficient`；`7.5 .. 15.0 GiB`（8 GB / 12 GB 笔记本）→ `Tight`（提醒已自动开启小内存减负，建议关掉大型软件或推荐用 16 GB+ 台式机）；`>= 15.0 GiB` → `Good`。
     - **当前空闲内存（`avail_memory`）**：`< 2.2 GiB` → `Insufficient`；`2.2 .. 4.0 GiB` → `Tight`；`>= 4.0 GiB` → `Good`（若本机已有 Hunter 容器在跑则放宽 1.5 GiB）。
     - **处理器核心（`cpu`）**：`< 2` → `Insufficient`；`2 .. 4` → `Tight`；`>= 4` → `Good`。
     - **可用磁盘空间（`disk`）**：`< 15 GiB` → `Insufficient`；`15 .. 25 GiB` → `Tight`；`>= 25 GiB` → `Good`。
     - **系统与虚拟化（`os_virt`）**：macOS `< 13` → `Insufficient`；已运行的 Docker 分配内存 `< 2.6 GiB` → `Tight`；其余正常 → `Good`。
   - 在 `commands.rs` 与 `lib.rs` 注册 `hardware_check` 命令；在 `feedback.rs` 诊断包概要（`summary`）中新增 `硬件: CPU {} 核 · 总内存 {} · 当前可用 {} · 评级 {}`。
2. **8 GB 小内存笔记本自动减负与容器内存不足（OOM）精准识别**：
   - `src-tauri/src/runtime/builtin.rs`：抽取出纯函数 `vm_params_for(cores, mem_gib, disk_free_bytes)`，当 `mem_gib <= 9`（8 GB 内存机型）时分配 `3` GiB 虚拟机内存，为宿主机多留 1 GiB 可用内存；`mem_gib > 9` 保持 `(mem_gib / 4).clamp(4, 8)`。
   - `src-tauri/src/compose.rs`：新增 `is_oom_status`、`is_service_oom` 与 `oom_error_message`，在 `wait_healthy` 检测到容器異常退出或超时未就绪且满足 `ExitCode == 137` 或 `OOMKilled == true` 时，直接返回大白话说明：`电脑可用内存不足，服务 {service} 在启动时被系统强行终止（内存溢出）。建议先关闭其他占内存的大型软件后重试，或在 16 GB 及以上内存的电脑（如台式机）上运行。`
3. **Windows 自动安装 Docker 全流程闭环（`src-tauri/src/runtime/win_install.rs`）**：
   - `ensure_wslconfig_in`：按本机物理内存（8 GB → `3500MB`、12~16 GB → `6GB`、24 GB+ → `8GB`）自动生成 `%USERPROFILE%\.wslconfig`，**若用户已有 `[wsl2]` 与 `memory=` 配置则绝不覆盖**。
   - `preconfigure_docker_desktop_in`：自动合并写入 `%APPDATA%\Docker\settings-store.json` 的 `"DisplayedOnboarding": true`、`"licenseTermsVersion": 2`、`"AutoStart": true` 及非系统盘 `"dataFolder"`，保留用户已有键。
   - `installer_args`：构造静默安装参数 `install --quiet --accept-license --backend=wsl-2 --always-run-service`，当选中非系统盘（如 `D:\Hunter`）时自动追加 `--installation-dir=D:\Hunter\DockerApp` 与 `--wsl-default-data-root=D:\Hunter\docker-data`。
   - `elevate.rs` / `guard.rs` / `chain.rs` / `docker.rs`：新增 `Op::WinInstallDocker`、`Route::WinDockerDesktop` 与 `PRIVILEGED_OPS` 白名单校验，支持单次 UAC 提权启用 WSL2 特性并静默安装 Docker Desktop，返回码 `3010`（需重启）时自动写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce`（`HunterLauncherResume`）实现重启自动续装。
4. **前端欢迎页（`Welcome.tsx`）与 Docker 页（`Docker.tsx`）及中英文国际化更新**：
   - `src/pages/Welcome.tsx`：新增 `HardwareCheckCard`，支持绿灯紧凑安心提示、黄灯琥珀色提醒卡片、红灯警告卡片及「重新检测」按钮。
   - `src/i18n/zh-CN.ts`、`src/i18n/en.ts`、`src/lib/types.ts`、`src/lib/ipc.ts`、`src/lib/demo.ts`：补齐 `HwReport` 类型、IPC 调用、演示模式三档数据（支持 `?hw=tight` / `?hw=insufficient`）与中英文文案。
