## 一、背景与需求

在日常客户支持与排障中，用户遇到问题时往往需要把启动器与容器的后台日志发给开发者定位。此前上传日志入口仅出现在部分特定报错卡片或升级失败界面中，用户在常规界面（如欢迎页、运行面板、配置页等）难以一眼找到上传日志的地方；且上传后需要直观地看到日志编码（如 `HL-7K3Q9F`）以及对应的日志界面。

本轮 I21 迭代目标：
1. **顶部标题栏常驻「上传日志」图标按钮**：在标题栏右侧（设置齿轮按钮旁）新增带有上传标识的日志图标按钮，在任意页面点击即可一键触发脱敏后台日志上传，并直接打开日志页面。
2. **日志页面顶部新增「日志编码」横幅**：进入日志页后，顶部直接呈现日志编码横幅：
   - 上传中展示实时进度提示；
   - 上传成功后用大号等宽琥珀色字体醒目展示 8 位日志编码（如 `HL-DEMO01`），并提供「复制编码」「查看已上传内容」「重新上传」按钮；
   - 若尚未在当前会话上传，但本机存在上次上传记录（`localStorage` 中的 `hunter.lastTraceCode`），自动展示上次的日志编码与上传时间，支持一键复制或立即重新上传；
   - 点击「查看已上传内容」可弹窗查看经过脱敏与严格出口闸检查的完整日志原文。
3. **日志界面同屏展示**：横幅下方完整保留启动器日志 / 容器日志切换、按服务筛选、实时滚动、脱敏复制与导出诊断包功能。

## 二、本轮改动清单

1. **图标组件（`src/components/Icons.tsx`）**：
   - 新增 `UploadLogIcon` 矢量图标组件（文档轮廓 + 向上箭头），尺寸与视觉风格与标题栏 `Gear` 齿轮图标保持一致。
2. **全局状态与触发机制（`src/state/context.ts`、`src/state/store.tsx`）**：
   - `Store` 接口新增 `logUploadTrigger: number` 与 `triggerLogUpload: () => void`；
   - 调用 `triggerLogUpload()` 时自动将 `overlay` 切换为 `'logs'` 并递增 `logUploadTrigger`，使日志页感知并立即启动后台脱敏日志采集与上传。
3. **顶部标题栏（`src/components/TitleBar.tsx`）**：
   - 在标题栏右侧（设置按钮左侧）新增「上传日志」图标按钮（`data-testid="titlebar-upload-log"`），带悬浮提示「上传日志并查看日志编码」，点击触发 `triggerLogUpload()`。
4. **日志页面与日志编码横幅（`src/pages/Logs.tsx`）**：
   - 顶部新增 `data-testid="logship-banner"` 横幅区域，覆盖四种状态：上传中、本次上传完成（大号字体展示 `traceCode`）、展示上次上传编码记录、首次未上传引导；
   - 接入 `ipc.logshipPreview` 与 `ipc.logshipUpload`，自动勾选默认分节并执行脱敏上传，上传成功后将编码与时间写入 `hunter.lastTraceCode` / `hunter.lastTraceAt`；
   - 新增「查看已上传内容」弹窗（`Modal`），原样展示发送给排障库的脱敏正文；
   - 支持 `HUNTER_DEMO_PAGE=logs-uploaded` 演示模式首屏直接渲染上传完成态与日志编码 `HL-DEMO01`。
5. **中英文文案与演示桩（`src/i18n/zh-CN.ts`、`src/i18n/en.ts`、`src/lib/ipc.ts`）**：
   - 新增 `titleBar.uploadLog` 及 `logs.uploadBannerTitle` / `codeLabel` / `copyCode` / `reupload` / `viewUploadedBody` 等完整中英文词条；
   - 零终端命令、零违规英文词，通过 `check-wording.py` 校验。
6. **单元测试与并发锁加固（`src/lib/logship.test.ts`、`src-tauri/src/assist/actions.rs`、`src-tauri/src/logship.rs`）**：
   - 新增 `src/lib/logship.test.ts`：覆盖 `Logs` 页面上传完成后展示日志编码 `HL-TEST88`、复制日志编码，以及标题栏点击「上传日志」按钮自动打开日志页并完成上传拿到日志编码的完整交互链路；
   - 为 `actions.rs` 两条内置运行时路径单测补充 `test_home` 隔离、为 `logship.rs` 两条 `ensure_machine_id` 单测补充 `log::test_lock()`，消除多线程并行跑测试时的全局状态竞争。
