## 四、当前已知的关键约束（M0 实测得出，详见预研结论）

| 约束 | 影响的里程碑 |
|---|---|
| 网关四类 key 错误（格式错 / 不存在 / 已吊销 / 未带）返回**完全相同**的 401 体，无法区分 | M2 已按此实现（本地判格式 + 401 统一文案） |
| **`docker compose --progress json pull` 的进度流在 stderr 上**，不是 stdout（M2 实测修正 M0 §5.1） | M2 已修 |
| `Extracting` 行**只有** `current` 没有 `total`，算不出解压百分比 | M2 已按此实现（显示「解压中」） |
| `docker pull` 在非 TTY 下**完全没有**逐层进度，只有三行结果 | M2 已绕开（走 compose） |
| hunter-community 的 Release **没有任何 assets** | M2 已绕开（raw + sha256 校验 + 内置副本兜底） |
| 阿里云 ACR 与 Docker Hub 上都没有镜像；国内源改用**腾讯云香港** `hkccr.ccs.tencentyun.com/agentpit`（广州区已停用） | M2 已接入（两源真实测速） |
| GHCR 镜像六个合计 **849 MB**（amd64 压缩，manifest 实测），不是视觉稿写的 2.1 GB | M2 已按实测上屏 |
| **两个工作目录会抢同一个 compose 项目名 `hunter`**，后开的会顶掉先装好的（M2 实测撞到） | I 轮 · 待办池 P0-5（M3 未做） |
| 方案第 13 节列的**六个 api 新增接口全部不存在**；M3 把 api 容器上能读的接口逐条探了一遍，不登录能读的只有 `/api/health`、`/api/setup/status`、`/api/setup/llm/quota`、`/api/setup/env-check` 四条 | M3 已按此实现：「数据源」卡接上 `/api/setup/status`，「今日对话」「晨报」显示「—」并在界面上列出缺哪四条接口（M3 §14） |
| `.deb` **3.32 MiB** 远低于目标，但 **`.AppImage` 75.11 MiB 超出「≤40 MB」近一倍**（自带 WebKitGTK，压不下去。M3 真打真装复核过） | M4 · 发布策略与 README 文案 |
| 安装包文件名带空格（Tauri 用 `productName`），下载地址会变成 `%20`；CI 里已改名成 `hunter-launcher_<版本>_amd64.*` | M4 · 发布流水线要用同一套命名 |
| 字体是**本地打包的子集**，只含仓库里出现过的字形；容器日志里的中文（如「迁移」）靠系统中文字体回落（M3 装 `fonts-noto-cjk` 前后对比验证过回落有效） | 所有涉及界面的里程碑 · 加新文案要跑 `scripts/build-fonts.py`，CI 的 `check-fonts.py` 会拦 |
| AppImage 打包需要 `xdg-utils`（Tauri 官方依赖清单里没有），缺了会在最后一步失败 | M4 · CI 依赖 |
| 2 核 8G 机器上 Tauri 冷编译耗时与峰值内存见预研结论第六节 | M1 · CI 超时设置 |
| `cargo build --release` **不等于** `tauri build`：前者不带 `custom-protocol` 特性，产物会去连 devUrl 而不是内嵌前端，表现为白屏（M1 §9 实测） | M4 · 打包脚本 |
| 视觉稿是 2 倍图（2360×1520 ↔ 约 1180×760 逻辑像素），量到的像素值要 ÷2 | 所有涉及界面的里程碑 |
