## 四、当前已知的关键约束（M0 实测得出，详见预研结论）

| 约束 | 影响的里程碑 |
|---|---|
| 网关四类 key 错误（格式错 / 不存在 / 已吊销 / 未带）返回**完全相同**的 401 体，无法区分 | M2 |
| `docker compose --progress json pull` 的 `Downloading` 行带 `current`/`total`/`percent`，`Extracting` 行**只有** `current` | M2 |
| `docker pull` 在非 TTY 下**完全没有**逐层进度，只有三行结果 | M2 |
| hunter-community 的 Release **没有任何 assets**，compose 只能从 raw.githubusercontent 按 tag 取 | M3 |
| 阿里云 ACR 与 Docker Hub 上**都没有**可用镜像，只有 GHCR | M2 · 需用户决定 |
| GHCR 镜像六个合计约 **810 MiB**（amd64 压缩），不是视觉稿写的 2.1 GB | M2（文案要改） |
| 方案第 13 节列的**六个 api 新增接口全部不存在**（源码里一行都没有） | M3 · 运行面板两张卡片无数据来源 |
| `.deb` 2.28 MiB 远低于目标，但 **`.AppImage` 74 MiB 超出「≤40 MB」近一倍**（自带 WebKitGTK，压不下去） | M4 · 发布策略与 README 文案 |
| AppImage 打包需要 `xdg-utils`（Tauri 官方依赖清单里没有），缺了会在最后一步失败 | M4 · CI 依赖 |
| 2 核 8G 机器上 Tauri 冷编译耗时与峰值内存见预研结论第六节 | M1 · CI 超时设置 |
