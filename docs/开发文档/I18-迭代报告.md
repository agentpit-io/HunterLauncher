## 一、四张卡的改动点

### P0-1 · 「装了但没在跑」时替用户拉起来（口径 A）

**根因是一句过时的注释 + 四处各自为政的「这个平台不做」判断。**
`runtime/docker.rs` 原来写着「mac / Windows 上启动 Docker Desktop 要用户自己点，启动器替他点不了」——
可同一个仓库里 macOS 那条路早就用 `open -a Docker` 做到了（不需要管理员），Windows 上从来没有被验证过，
而 `Docker Desktop.exe` 同样是**用户态程序**。

| 文件 | 改动 |
|---|---|
| `src-tauri/src/runtime/mod.rs` | 新增 `Os`（`Mac` / `Windows` / `Linux`）与 `const OS`。**做成显式值而不是到处 `cfg!`** —— 理由见下面「三平台怎么测的」 |
| `src-tauri/src/assist/actions.rs` | `start_runtime_argv` 改成 **`pub`**；`orbstack`/`docker-desktop` 那一档拆成**纯函数** `desktop_app_argv(app, os, open, dd)`：macOS 给 `open -a Docker/OrbStack`（**一个字没改**）、Windows 给定位器找到的 `Docker Desktop.exe`（**本轮的核心**）、Linux 如实拒绝（那边走 `systemd` 那一档） |
| `src-tauri/src/runtime/which.rs` | Windows 的已知位置清单补上 `C:\Program Files\Docker\Docker` 与 `~\AppData\Local\Programs\Docker\Docker` —— `Docker Desktop.exe` 就在这一层（CLI 在下面的 `resources\bin`），排在它们后面 |
| `src-tauri/src/runtime/docker.rs` | `try_start_daemon(say)` **不再是「只 Linux」**：先按平台决定拉谁（纯函数 `start_app_on`）→ 调 `start_runtime_argv`（**不在这里抄第二份 argv 构造**）→ 复用 `chain::wait_daemon` 等就绪 → 如实回报。新增 `start_app()`：Windows 上先用 `detect()` 问「装没装」与 `wsl`，**WSL2 缺就不拉**（别把「WSL 缺」讲成「Docker 缺」） |
| `src-tauri/src/commands.rs` | `start_daemon` 命令改传 `say`（日志里能看到在等什么）；新增 `ensure_user_runtime_up()` 与纯函数 `should_start_user_runtime(installed, daemon, wsl)`；`ensure_runtime_up()` 按**口径 A** 扩展，并把它上面那段 I9 起的自我约束注释**改写并写清理由** |

超时与话术：拉起命令最多 30 秒、等就绪最多 **60 秒**（`START_WAIT`），
等不到就如实说「已经拉起来了，但等了 60 秒后台服务还没就绪。可以再点一次『启动运行时』重试」。

### P0-2 · 文案按「装没装」与「跑没跑」两态分开

| 文件 | 改动 |
|---|---|
| `src-tauri/src/runtime/chain.rs` | `platform_cannot_install()` 从「按平台分」改成「**按状态分**」：`platform_cannot_install(&DockerInfo)` → 纯函数 `platform_cannot_install_on(os, installed, daemon_running)`。**装了没在跑**那一档指向「启动运行时」；**装了也在跑**那一档说清是版本问题、**别叫人家去装**；**没装**那一档才讲这个平台能不能替你装 |
| `src-tauri/src/selfcheck.rs` | 新增 `runtime_down_headline()`；`review()` 里 `Posture::RuntimeDown` 且项目名是我们的时**才**多跑一次 `detect()`（这一档本来就问不出来，多跑一次值得），headline 按两态分开 |
| `src-tauri/src/assist/auto.rs` | `cannot_do` 里 `E_DOCKER_MISSING` 那一条原来标题写死「这台电脑上没有 Docker」—— 现在按 `installed × daemon_running` 分三种标题 |

| `src/pages/Docker.tsx` | 「装了没在跑」那一档**单独说一句**（原来只摆 docker 的原话，没告诉用户下一步），等待期间也有一句（不能静默卡住） |

### U5 · 升级过程要看得见网速与剩余时间

这条链**一个环节都不缺，只差界面没接**（后端 `PullProgress` 自带 `speedBps`/`etaSeconds`、
`EV_PULL` 每条都发、`ipc.onPullProgress()` 已导出无人调用、`t.pull.*` 全是死文案）。

| 文件 | 改动 |
|---|---|
| `src/lib/types.ts` | `PullProgress` **补 `netBytes`** —— 没有它，「这次下载了多少」只能拿 `downloadedBytes` 去编 |
| `src/lib/pull.ts`（新） | **纯函数** `pullView(p, t)`：那一块显示什么、不显示什么，全在这里。三条诚实性红线都落在这个文件里（见下） |
| `src/lib/pull.test.ts`（新） | 10 条单测，逐条钉红线 |
| `src/pages/Update.tsx` | 订阅 `onPullProgress`；**监听器只把最新一份存进 ref，上屏交给和轮询共用的一秒定时器**（刷新频率不高于每秒一次，不让整块面板跟着每条进度重渲）；六个镜像的状态与字节可折叠 |
| `src-tauri/src/compose.rs` | `PullAggregator::set_attempt` 在换源时**清掉速度样本** —— 否则那个 20 秒的滑动窗口会把两条完全不同的链路掺在一起算平均速度 |
| `src/lib/ipc.ts` / `src/state/store.tsx` / `src/lib/demo.ts` / `scripts/screenshot.sh` | 演示态两页 `update-running` / `update-retry`（真机上那一块要真点两下才出得来，截图脚本不好稳定定位，I17 的 `update-no-tag` 就是栽在这上面） |

**三条诚实性红线（写在 `pull.ts` 的文件头，由单测逐条钉住）**：

1. **总量没算出来时写「正在算…」，不写 0%**（`totalBytes == 0` → `percent` 是 `null`）；
2. **`speedBps` / `etaSeconds` 为 `null` 时写「剩余时间未知」**，不许拿「已用时 ÷ 已完成比例」凑数；
3. **「本次已下载」用 `netBytes`**，`downloadedBytes` 只做进度条的分子（本机全都有时直接写「这些镜像本机都已有，没有下载」）。

## 二、三平台怎么测的（本机是 Linux）

「Windows 上该启动 `Docker Desktop.exe`」这条断言**用 `cfg!` 根本写不出来** ——
`cfg!` 编译期就定死了，而开发机与 CI 的 Linux job 只有一种取值。
所以把平台做成显式参数（`runtime::Os`），三个分支都能在任意一台机器上被钉住：

| 单测 | 断言 |
|---|---|
| `actions::tests::启动桌面运行时的命令三平台各一条` | macOS `[open, -a, OrbStack]` / `[open, -a, Docker]`；**Windows `[C:\Program Files\Docker\Docker\Docker Desktop.exe]`**；Windows 上 `orbstack` 如实拒绝；定位器找不到那个 exe → 错误码是 `DockerMissing`（是「没装」不是「做不到」）；Linux 两条都拒绝 |
| `actions::tests::linux_上桌面那一档与_systemd_那一档是两回事` | Linux 上 `start_runtime_argv("systemd")` 仍是 `[systemctl, start, docker]` |
| `docker::tests::该拉起哪个运行时按平台定` | Linux→`systemd`（与那张 app 表无关）；Windows→`docker-desktop`；macOS→第一个「装=true、跑=false」的；`builtin` 不在这一档里挑；都跑着 / 没装 / **读不到（`None`）** → 如实拒绝 |
| `commands::tests::只在装了但没在跑时才替用户拉起运行时` | `should_start_user_runtime` 的七行真值表（含 `installed=false` 与 `wsl=Some(false)` 两条**不插手**） |
| `chain::tests::平台不支持时不叫用户去敲命令` | 三平台 × 三状态，九句话里都不许出现「终端 / 命令行 / 复制 / sudo / apt-get / curl / **请手动启动**」 |
| `chain::tests::没装时不说装着` / `装了没在跑时不说去装` / `装着也在跑时不叫去装` | A2-1 / A2-2 直接对应；两态的话**必须不一样** |
| `selfcheck::tests::运行时没在跑时_headline_要说清是装了没跑` / `问不出来时不猜是装了没跑` | `Posture::RuntimeDown` 两态；`None`（没去问）走原来那一句，**不猜** |
| `compose::tests::换源之后速度样本作废重算` | `set_attempt(2)` 之后 `speed_bps` / `eta_seconds` 回到 `None`，而 `net_bytes` 不丢 |
| 前端 `src/lib/pull.test.ts`（10 条） | 红线 1/2/3 各一条；`downloadedBytes=132 MB` 而 `netBytes=28 MB` 时，net 那一行**只许出现 28**；`etaSeconds=null` 时整句里**一个数字都没有**（`/\d/` 断言）；`netBytes==0` 时不出现「已下载 X」 |

`scripts/gate-mirrors.sh --self-test` 5 条：同步成功+校验通过→0；**同步完成但失败**→非零；
**同步被跳过**（`conclusion=skipped`）→非零；一直没跑完→等超时后非零；校验说镜像不齐→非零。
另外每条都断言 `-f tags=1.2.3` 拼对了，且**同步没成功的两条路里校验脚本一次都不许被调用**。

## 五、P1 闸门的边界（必须说清，否则等于谎报）

用户拍板的那句是「发布侧加『镜像先就位、再点亮升级入口』的闸门」，方案 §P1 给的**最小改法就在
`release.yml`**。本轮的实现严格照此，但有两个必须写下来的边界：

1. **它挂在启动器的发布链上，而客户撞上的窗口在 `hunter-community` 的发布链上。**
   今早那件事是「hunter-community 发了 v1.2.3 → 升级按钮亮了 → 国内源还没同步」；
   而启动器（0.1.x）的 Release 是**另一条独立的线**。所以这道闸门能保证的是
   「**发启动器那一版的时候**，当前的 hunter 版本在两源上都齐」，**不能**保证
   「hunter-community 每一次发版时镜像都齐」。
   真正闭合那个窗口要在 `hunter-community` 仓库里做同样的事 —— 而本轮的红线是只改 `HunterLauncher`。
2. 因此本轮的写法是：闸门触发 `cn-mirror.yml` 时，**版本默认取 `hunter-community` 的最新正式 Release**
   （与 `cn-mirror.yml` 不带入参时的口径完全一致），也可以用 `workflow_dispatch` 的
   `hunter_version` 显式指定。

`--self-test` 验过的是**判定逻辑**（什么算成功、什么算失败、超时怎么算、参数拼得对不对）；
**没有验过**「真的派发了一次 workflow、真的轮询了 GitHub API、真的拦下了一次 Release」。

| V13 | Windows 上 WSL2 缺的那一档（`wsl=Some(false)`） | 同上 | 说「Docker Desktop 装着，但它要的 WSL2 不在这台电脑上」，**不**说成「没装 Docker」 |

## 七、本轮没做什么、以及为什么

- **不在 Windows / Linux 上做「安装 Docker / WSL2」那条链路** —— 要管理员、要重启，是另一个量级的工程。
  这是任务书写死的边界，`routes()` 在非 macOS 上**仍然返回空**（有意留空，见 `chain.rs` 的注释）。
- **不改 `docker-compose.yml`、不动数据卷与数据库、不新增遥测**（任务书红线）。
- **不动 I17 已定的交互**。`quit-guard`（升级中退出被拦）、首页一级按钮组、`update-no-tag`
  这些一个字节都没改 —— 与本轮唯一有交集的 `Update.tsx` 是**新增**那一块进度面板，既有块按原样保留。
- **不发版、不打 tag**（用户拍板）。

## 八、溜出去的两件事（记进待办池）

1. **`probe::runtime_apps()` 在 Windows 上根本不列 Docker Desktop** —— 它只列 macOS 的两个 app
   与内置运行时 / 用户自己的 colima / Linux 的 systemd。后果：那台客户机上
   `诊断助手（规则层）：unknown · confident=false · 动作 0 个`（09:06 那份日志里就有这一行），
   而它其实是「装了没在跑」这个**最好修**的一档。本轮**没有动它** ——
   P0-1 的任务书只让改到 `ensure_runtime_up`，而给 Windows 加一条 app 记录会连带改
   `builtin::decide()` 的行为（`StartExisting`），风险面超出这一轮。记 P1-54。
2. **U5 那一块的首屏可见性**（见第四节末尾）。记 P1-53。
