# Hunter 轻启动器（Hunter Launcher）技术方案

> 目标：一个 20–40 MB 的跨平台桌面程序，把 hunter-community 的部署从"clone → 改 .env → 命令行"变成"下载 → 填一把 key → 等 3 分钟"。业务代码零改动，全部工作在部署层与 api 的少量新增接口。
> 同时落地四项反馈机制：Web 反馈按钮、opt-in 匿名遥测、版本检查、Release Notes 回应。
> 依赖：模型网关（llm.agentpit.io）已上线，使"一把 key"成立；镜像瘦身完成后体验更好但不是前置条件。
> 版本 1.0 · 2026-09-19

## 1. 目标、非目标与成功标准

### 目标

- 三平台（Windows 10/11 x64、macOS 12+ Intel/Apple Silicon、Ubuntu 22.04+/Debian 12+ x64）
- 用户只需一把 hunter key；模型默认走网关，高级用户可切自带 key
- 检测 / 引导安装 Docker，拉镜像，生成配置，启动，打开浏览器
- 托盘常驻：启动 / 停止 / 重启 / 查看日志 / 检查更新 / 反馈
- 安装包 ≤ 40 MB，冷启动 ≤ 2 秒
- 首次成功率（从打开启动器到浏览器出现对话界面）≥ 85%

### 非目标

- 不替代 Docker，不把 Hunter 打包成原生程序
- 不做多实例管理（一台机器一套 Hunter）
- 不做用户账号系统；hunter key 就是身份

### 成功标准（上线 30 天）

| 指标 | 目标 |
|---|---|
| 启动器下载 → 首次对话成功率 | ≥ 85% |
| 首次启动中位耗时（含拉镜像） | ≤ 5 分钟（国内镜像源） |
| 通过启动器提交的反馈占全部反馈比例 | ≥ 50% |
| 遥测 opt-in 率 | ≥ 40% |

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 桌面框架 | **Tauri 2.x**（Rust 后端 + Web 前端） | 包体 10–30 MB（Electron 80 MB+）；官方 updater、tray、shell、fs 插件齐全；签名流程成熟 |
| 前端 | React + TypeScript + Tailwind（与 apps/web 同栈） | 团队熟悉；可复用设计 token |
| 与 Docker 交互 | 调用 `docker` / `docker compose` CLI（子进程） | 与用户手工部署完全一致，问题可复现；避免直接对接 Engine API 在三平台 socket / named pipe 的差异 |
| 配置存储 | `~/.hunter/` 下的 TOML + `.env` | 可读、可手改、可被 compose 直接消费 |
| 日志 | Rust `tracing` → 本地滚动文件 | 反馈时脱敏后随附 |
| 遥测 / 反馈上报 | HTTPS POST 到 `https://telemetry.agentpit.io`（Cloud Run） | 与模型网关同一套鉴权（hunter key） |
| 更新 | Tauri Updater + GitHub Releases（`latest.json` 签名清单） | 免服务器；国内可加镜像地址 |
| 安装包 | Windows: NSIS `.exe` + MSI；macOS: `.dmg`（通用二进制）；Linux: `.AppImage` + `.deb` | 覆盖主流 |

不选 Electron 的原因：体积、内存、以及 Tauri 对这种"薄壳 + 系统调用"场景更贴合。不选纯 Go/TUI 的原因：目标用户里有一部分正是怕命令行的人。

## 4. 启动器状态机

```
Idle
 └─ CheckDocker ──(缺失)──> InstallDockerGuide ──(用户完成)──> CheckDocker
      │(存在)
      ▼
 CheckDaemon ──(未运行)──> StartDaemon / 提示手动启动 ──> CheckDaemon
      │(运行)
      ▼
 NeedKey ──(输入)──> ValidateKey ──(无效)──> NeedKey
      │(有效)
      ▼
 ChooseModel（默认网关；可选自带 key）
      ▼
 SelectRegistry（自动测速）
      ▼
 Pulling（流式进度，每镜像百分比）──(失败)──> Error(PullFailed) ──重试/换源
      ▼
 WriteConfig（.env / compose 覆盖文件）
      ▼
 Starting（compose up -d → 轮询 6 服务 healthy，超时 180s）──(失败)──> Error(StartFailed) ──看日志/反馈
      ▼
 Ready（打开浏览器；托盘变绿；首日 Onboarding 提示）
      │
      ├─ Stop → Stopped → Start → Starting
      ├─ UpdateAvailable → Upgrading（pull 新 tag → up -d）→ Ready
      └─ Quit（询问是否停止容器）
```

每个状态转换写一条本地日志与一条遥测事件（若已 opt-in）。

## 5. 模块设计

### 5.1 `runtime::docker`

- 探测顺序：`docker version --format json` → 解析 Client/Server 版本；Server 缺失即 daemon 未运行
- 兼容多种运行时：Docker Desktop、Docker Engine（Linux）、OrbStack（mac）、Colima（mac）、Podman（`podman-compose` 或 `podman` 的 docker 兼容 socket，标注为实验支持）
- 最低版本：Docker Engine 24 + Compose v2.20；低于则提示升级
- 引导安装：按平台打开官方下载页或执行安装脚本（见第 6 节），并在页面上留"我已装好，重新检测"

### 5.2 `compose`

- 工作目录 `~/.hunter/app/`，内含从 Release 资产下载的 `docker-compose.yml`、`docker-compose.launcher.yml`（覆盖文件）、`.env`
- 所有命令带 `--project-name hunter`，与用户手工部署不冲突
- `pull`：解析 `docker compose pull` 的进度行（或 `docker pull` 逐镜像 + `--progress plain`），映射为每镜像百分比
- `up -d` 后轮询 `docker compose ps --format json`，读 `Health` 字段；同时对 `http://localhost:3100/api/health` 做 HTTP 探测
- `logs --tail 200 <service>` 供日志面板与反馈脱敏使用

### 5.3 `config`

- `~/.hunter/launcher.toml`：启动器自身设置（语言、遥测 opt-in、镜像源、自动启动、Hunter 版本 tag）
- `~/.hunter/app/.env`：Hunter 配置；由模板 + 用户输入生成；生成后用户可手改，启动器每次启动前校验必填项
- `JWT_SECRET`：首次生成 48 字节随机 base64，之后不变（否则用户会掉登录）
- 端口冲突检测：3100 / 8000 / 3901 / 5432 / 6379 被占用时自动改用备用端口并写入 `.env` 与覆盖文件

### 5.4 `gateway`

- `POST https://llm.agentpit.io/v1/keys/validate`（携带 hunter key）→ 返回 `{valid, plan, daily_quota, used_today, models: [...]}`
- 无效 key：区分"格式错""不存在""已吊销""配额用尽"给不同文案
- 模型页展示可用模型别名（`hunter-default`、`hunter-deep`）与今日额度进度条
- 切换自带 key 时，前端展示与 README 一致的三项配置（BASE_URL / MODEL / API_KEY），并对 DeepSeek 自动勾选 `LLM_SCHEMA_SANITIZE=1`

### 5.5 `registry`

- 候选源：`registry.cn-hangzhou.aliyuncs.com/agentpit`、`docker.io/agentpit`、`ghcr.io/agentpit-io`
- 测速：对每个源发 HEAD 请求取 manifest（或拉一个 1 MB 的探针镜像）取耗时；国内默认 ACR
- 用户可在设置里手动固定

### 5.6 `updater`

- 启动器自更新：Tauri Updater 读取 `https://github.com/agentpit-io/hunter-launcher/releases/latest/download/latest.json`（备用国内镜像 URL），签名校验后下载安装
- Hunter 版本检查：每 6 小时对比 `~/.hunter/launcher.toml` 里的 `hunter_tag` 与 GitHub Release 最新 tag；有更新则托盘提示，用户确认后执行 `pull` + `up -d`；升级前自动 `pg_dump` 到 `~/.hunter/backups/`
- 升级失败自动回滚到旧 tag

### 5.7 `telemetry` 与 `feedback`

见第 11–12 节。

### 5.8 `tray`

- 菜单：打开 Hunter / 状态（运行中 · 已停止 · 更新中）/ 启动 / 停止 / 重启 / 查看日志 / 检查更新 / 反馈 / 设置 / 退出
- 退出时若容器运行中，询问"保持后台运行"或"一起停止"
- 开机自启（可选，默认关）

## 6. Docker 运行时适配（三平台）

### Windows

- 要求 Windows 10 21H2+ / 11，WSL2；启动器检测 `wsl --status`，缺失则引导 `wsl --install`（需重启，文案说明）
- Docker Desktop 下载页直达；安装后需登出/重启，启动器给出明确步骤
- 常见问题内置：Hyper-V/虚拟化未开启（BIOS）；WSL2 内存占用（引导写 `.wslconfig` 限 4 GB）；Clash/代理 TUN 模式导致容器无网（提示 NO_PROXY）
- 路径：`%USERPROFILE%\.hunter\`

### macOS

- 优先推荐 **OrbStack**（更轻、更快、Apple Silicon 友好）；其次 Docker Desktop；检测两者任意一个
- Apple Silicon 拉 arm64 镜像；Intel 拉 amd64；镜像必须双架构发布
- 路径：`~/.hunter/`

### Linux

- 检测 `docker` 与 `docker compose`；缺失则提供官方便利脚本一键安装（`get.docker.com`，国内用阿里云 Docker CE 源），完成后把当前用户加入 `docker` 组并提示重新登录
- 无 GUI 环境（服务器）：启动器提供 `hunter-launcher --headless` 子命令，纯 CLI 完成同样流程，供 SSH 用户使用
- 路径：`~/.hunter/`；AppImage 需 FUSE，`.deb` 为主

### Docker Desktop 授权提示

Docker Desktop 对 250 人以上或年收入超过 1000 万美元的企业收费。启动器在 Docker 引导页加一行说明，并把 OrbStack（mac）、Docker Engine（Linux）、Podman（实验）作为替代列出，这对私募客户是必要的合规提示。

`.env` 生成模板（关键项）：

```
LLM_API_KEY=<hunter key>

```

## 8. 模型网关与 key 校验

- 一把 key 同时用于模型网关与数据网关，网关侧按 key 分别计量
- 校验接口返回配额，启动器"模型"页显示：今日已用 / 配额、当前路由模型、"升级额度"链接
- 配额用尽时容器内 llm-shim 收到 429，Web 顶部显示"今日免费额度已用完，可等待明日或切换自带 key"——这条文案由 api 提供，启动器只负责在托盘同步提示
- 自带 key 模式下，启动器不上传任何厂商 key；仅存本地 `.env`

## 9. 镜像拉取与镜像源

- 拉取前显示总大小估算（从 manifest 读取各层 size 求和），让用户知道要等多久
- 并行拉 6 个镜像，展示每个的进度条与总进度
- 失败重试 3 次，自动切换下一个源
- 支持"离线包"：`hunter-images-<tag>.tar`（`docker save`），启动器提供"从文件导入"入口，给内网私募用

## 10. 更新

### 启动器自更新

- Release 时 CI 生成 `latest.json` 与各平台安装包及签名
- 启动器每次启动 + 每 24 小时检查；有更新时托盘提示，用户点击下载安装，重启生效
- 国内下载走 `dl.agentpit.io`（GCS + CDN 镜像 GitHub Release 资产）

### Hunter 升级

1. 检测到新 tag → 提示 Release Notes 摘要（从 GitHub Release body 取前 500 字）
2. 用户确认 → `pg_dump` 到 backups → 替换 compose 文件与 `OPENCODE_TAG` → `pull` → `up -d`
3. 健康检查通过 → 记录成功；失败 → 回滚 tag → `up -d` → 提示并引导反馈
4. 跨大版本（如 0.x → 1.x）时提示阅读升级须知

## 11. 反馈机制（四项）

### 11.1 Web 界面右下角反馈按钮

- 位置：apps/web 全局布局右下角浮动按钮；启动器托盘"反馈"菜单打开同一页面（`/feedback`）
- 表单：类型（部署问题 / 分析结果不对 / 想要的功能 / 其他）、描述、联系方式（可选）、勾选"附带诊断信息"
- 自动附带（用户可预览与删除）：
  - Hunter 版本、启动器版本、OS、Docker 版本、架构
  - 当前模型别名（不含 key）
  - 最近一次工具调用的脱敏摘要：工具名、耗时、状态码、错误类型；**不含输入参数中的股票代码以外的自由文本，不含模型输出**
  - `docker compose ps` 结果、api 与 opencode 最近 100 行日志（脱敏后，见 12.3）
- 提交到 `POST https://telemetry.agentpit.io/v1/feedback`；服务端创建内部工单，并在用户勾选"公开到 GitHub"时通过 bot 创建 issue（去掉联系方式）
- 提交后返回工单号；Web 侧"我的反馈"页显示状态（待处理 / 已回复 / 已修复于 vX）

### 11.2 opt-in 匿名遥测

- 默认关闭；首次启动向导最后一页询问一次，说明收集什么、不收集什么，可随时在设置关闭
- 关闭时本地队列清空，不再写入
- 事件与字段见第 12 节

### 11.3 版本检查

- api 启动时请求 `https://api.github.com/repos/agentpit-io/hunter-community/releases/latest`（超时 3 秒，失败静默；国内备用 `https://dl.agentpit.io/hunter/latest.json`），缓存 6 小时
- `GET /api/system/version` 返回 `{current, latest, release_notes_url, is_launcher}`
- Web 顶部横幅："新版本 vX 可用 · 查看更新内容 · 稍后提醒"；启动器环境下多一个"一键升级"按钮（调启动器本地接口，见 13.3）

### 11.4 Release Notes 回应社区

- Release Notes 模板增加固定段落「社区反馈回应」：列出本期回应的前三个问题（来源：issue / Discussions / 反馈工单），每条一句处理结果与链接
- 反馈工单被标记为"已修复于 vX"时，自动给留了联系方式的用户发一封通知（可退订）
- 每两周一次，与 Release 节奏一致

## 12. 遥测数据规范与隐私

### 12.1 原则

- 匿名：仅 `install_id`（随机 UUID，本地生成），不与 hunter key 关联；服务端不做二者的 join
- 最小化：只收计数与枚举，不收任何自由文本、股票代码、对话内容、模型输出
- 透明：设置页有"查看本机将要发送的数据"，展示队列原文
- 可退出：关闭即停，且可一键请求删除服务端历史（按 install_id）

### 12.2 事件表

| 事件 | 字段 | 触发 |
|---|---|---|
| `launcher_start` | version, os, arch, locale | 启动器启动 |
| `docker_detected` | runtime(kind), version, wsl(bool) | 检测完成 |
| `setup_step` | step, outcome(ok/fail), error_code, duration_ms | 向导每步 |
| `pull_done` | registry, total_mb, duration_ms, retries | 拉取完成 |
| `hunter_started` | hunter_tag, duration_ms, ports_remapped(bool) | 启动成功 |
| `hunter_daily` | conversations, tool_calls, skills_used(count), deep_analyses, morning_brief_enabled(bool), model_mode(gateway/own) | 每日一次汇总（由 api 本地聚合，启动器转发） |
| `skill_usage` | skill_name, count | 每日一次，仅内置 Skill 名，用户自建 Skill 记为 `custom` |
| `error` | component, error_code | 发生错误 |
| `update` | from_tag, to_tag, outcome | 升级 |

### 12.3 脱敏规则（反馈附带日志时执行）

- 正则移除：`sk-[A-Za-z0-9]{8,}`、`Bearer ...`、`hk_...`（hunter key 前缀）、邮箱、手机号、IP 地址（保留末段替换为 `x`）
- 移除 `.env` 中除 `LLM_BASE_URL` 主机名、`LLM_DEFAULT_MODEL`、`DATA_SOURCE_PROVIDER`、`OPENCODE_TAG` 以外的所有值
- opencode 日志中 `content:` / `text:` 字段整段替换为 `[redacted]`
- 用户可在提交前编辑

### 12.4 服务端

- Cloud Run `telemetry-ingest` → BigQuery（按天分区，保留 400 天）
- 反馈附件存 GCS，90 天后删除
- 每周一张看板：安装、首次成功率、各步骤失败率、日活安装、Skill 使用排行

| 接口 | 说明 |
|---|---|
| `GET /api/system/version` | 当前版本、最新版本、Release Notes URL、是否启动器环境 |
| `GET /api/system/health/detail` | 各依赖状态（DB / Redis / opencode / 网关可达 / 数据网关可达），供启动器状态页 |

启动器在 `127.0.0.1:37999` 提供一个只接受本机请求且带一次性 token 的极简 HTTP 服务，供 Web 页面调用"一键升级""打开日志"。token 由启动器写入 `.env` 的 `HUNTER_LAUNCHER_TOKEN`，api 注入到前端。

## 15. 安全

- hunter key 仅存 `.env`（文件权限 600）与内存；不写日志、不进遥测
- 启动器所有出站仅到：`llm.agentpit.io`、`telemetry.agentpit.io`、`api.github.com`、`dl.agentpit.io`、镜像源；列在设置页
- 子进程调用使用参数数组，不拼接 shell 字符串，防注入
- 本地接口仅监听 `127.0.0.1` 且需 token
- 更新包必须通过 Tauri Updater 的签名校验；公钥内置
- 反馈附件上传前本地脱敏，服务端再做一次

## 16. 签名、公证与分发

| 平台 | 要求 | 成本 |
|---|---|---|
| Windows | 代码签名证书（OV 起步；EV 可立即免 SmartScreen 警告） | OV 约 100–200 美元/年，EV 300–500 美元/年 |

不签名的后果：Windows SmartScreen 拦截、macOS "已损坏无法打开"，C 端与非技术用户会直接放弃。**签名是必做项。**

## 18. 错误处理与用户可见文案

| 错误码 | 场景 | 文案要点 | 动作 |
|---|---|---|---|
| `E_DOCKER_MISSING` | 未装 Docker | 一句话说明 + 平台安装按钮 | 引导安装 |
| `E_DAEMON_DOWN` | Docker 未运行 | "请启动 Docker Desktop / OrbStack" | 尝试启动、重检 |
| `E_WSL_MISSING` | Windows 无 WSL2 | 说明需重启 | 执行 `wsl --install` |
| `E_KEY_INVALID` | key 无效/吊销 | 区分原因 | 重新输入 / 申请链接 |
| `E_QUOTA_EXHAUSTED` | 配额用尽 | 明日恢复或自带 key | 跳转模型页 |
| `E_PULL_FAILED` | 拉取失败 | 显示源与错误 | 换源重试 / 离线导入 |
| `E_PORT_IN_USE` | 端口占用 | 已自动换端口 | 无需操作 |
| `E_START_TIMEOUT` | 180 秒未健康 | 指出哪个服务未就绪 | 看日志 / 一键反馈 |
| `E_PROXY_BLOCK` | 代理导致容器无网 | 提示 NO_PROXY 配置 | 文档链接 |
| `E_UPDATE_FAILED` | 升级失败 | 已回滚 | 反馈 |

所有错误页都有"一键反馈"按钮，预填错误码与诊断信息。
